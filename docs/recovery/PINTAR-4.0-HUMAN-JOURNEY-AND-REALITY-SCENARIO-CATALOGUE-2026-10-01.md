# PINTAR 4.0 — Human Journey & Reality Scenario Catalogue

**Date:** 1 October 2026  
**Status:** Draft human-experience checklist for canonical and implementation cross-check  
**Purpose:** Describe PINTAR 4.0 as things real people are trying to accomplish, including common real-world situations.

> **PINTAR is not a collection of features. PINTAR is the journey between them.**

This catalogue is intentionally written from the **human perspective first**. It must not be rewritten merely to match the current implementation.

---

## 1. How to use this catalogue

- **Journey** — a person wants to accomplish something.
- **Scenario** — something ordinary happens before, during, or after that journey.
- **Expected experience** — PINTAR provides a sensible, connected path that lets the person continue safely and understand what happens next.

When this catalogue is later checked against PINTAR, assess each item against both the agreed/canonical PINTAR 4.0 scope and the current implementation/evidence.

Suggested scope classifications: **SUPPORTED BY CANONICAL SCOPE**, **OWNER RULING NEEDED**, **OUTSIDE PINTAR 4.0 / LATER VERSION**.

Suggested implementation classifications: **CONNECTED**, **DISCONNECTED**, **PARTIAL**, **MISSING**, **WRONG**, **UNPROVEN**.

Do not silently change the intended human journey to make existing code pass.

# 2. Student Journeys

## Entering PINTAR

### STU-J01 — Student wants to start learning for the day
Open PINTAR → identify/sign in → arrive at learner home → immediately understand:
- what I have accomplished;
- what is incomplete;
- what needs attention;
- what I should do next.

### STU-J02 — Student wants to continue where they stopped yesterday
Sign in → PINTAR remembers appropriate progress → clear continuation path → resume at a sensible point.

### STU-J03 — Student wants to find a subject
Home → subjects → select subject → see chapters/learning available → understand the status of each.

### STU-J04 — Student wants to start a new chapter
Select chapter → understand what the chapter contains → pre-test if required → lesson → activities → post-test → result → next action.

### STU-J05 — Student wants to resume an incomplete chapter
Return → PINTAR shows incomplete state → continue rather than accidentally restart.

## Assessment and learning

### STU-J06 — Student takes a pre-test
Enter → instructions → answer → submit → result/state recorded → proceed naturally into learning.

### STU-J07 — Student works through a lesson
Lesson → content/media/activity → progress saved → clear navigation → completion.

### STU-J08 — Student takes a post-test
Start → answer → submit → evaluation → understandable result.

### STU-J09 — Student performs well
Result → understands achievement → knows whether chapter is complete → sees next appropriate action.

### STU-J10 — Student performs poorly
Result → no humiliating/dead-end experience → understands what needs attention → remediation/reinforcement → appropriate next attempt/action.

### STU-J11 — Student wants to review something already completed
History/progress → subject/chapter → review previous material/results where allowed.

### STU-J12 — Student has several assignments
Home clearly prioritises them rather than presenting an undifferentiated list.

### STU-J13 — Student has nothing currently assigned
PINTAR gives a meaningful state rather than a blank/dead dashboard.

# 13. High-Probability Reality Scenarios

These scenarios are intentionally ordinary. They are selected because they are likely to happen in real schools, have meaningful consequences, or exercise important connections between parts of PINTAR.

### RS-01 — Student forgets password on Monday morning
Can the student recover access through a natural, age-appropriate path and return to learning without losing history or requiring an engineer?

### RS-02 — Student walks away from a shared computer without signing out and returns 10 minutes later
What does PINTAR protect? What does the student see on return? Is progress preserved? Is re-entry appropriate to the device context?

### RS-03 — Another student sits at that computer before the first student returns
Can the second student see the first student's information? Can identity switch safely and naturally?

### RS-04 — Student loses their PINTAR card
Can normal school personnel resolve this without technical/operator intervention while protecting identity?

### RS-05 — Student accidentally closes the browser halfway through a lesson
Can the student return and continue from an appropriate point without losing progress or creating duplicate state?

### RS-06 — Wi-Fi drops halfway through an assessment
What is preserved? What is visibly pending? Can the student reconnect safely without corrupting assessment integrity?

### RS-07 — Student clicks Submit twice because the network is slow
Does PINTAR safely prevent duplicate submissions/results while giving understandable feedback?

### RS-08 — Student gets a low post-test result and does not know what to do next
Does PINTAR turn the result into a clear next action rather than a dead end?

### RS-09 — Student has finished everything assigned and opens PINTAR again tomorrow
Does the learner home provide a meaningful state and next direction?

### RS-10 — Teacher walks into class and decides: “I want a five-question quiz now”
Can the teacher go from intent → class/context → questions → launch → student responses → useful results quickly and naturally?

### RS-11 — Teacher has only one minute before class starts to prepare that quiz
Does Uji Cepat deliver the intended speed without hidden setup or technical knowledge?

### RS-12 — Teacher finishes the quiz and immediately asks: “Who didn't understand this?”
Can PINTAR turn responses into actionable information rather than just scores?

### RS-13 — Teacher notices afterward that one question was wrong or ambiguous
Can the problem be corrected without silently rewriting historical evidence or producing inconsistent results?

### RS-14 — Teacher wants to add one supplementary lesson without changing centrally supplied content
Can local educator content coexist naturally with centrally distributed content?

### RS-15 — Teacher is absent and another teacher takes the class
Can an appropriately authorised substitute understand what is happening and continue learning without unsafe access?

### RS-16 — New teacher joins halfway through the semester
Can the teacher be onboarded, obtain the right context and continue an existing class without rebuilding it?

### RS-17 — School admin needs to onboard an entire new class
Can normal school administration accomplish this efficiently rather than repeating an impractical one-person-at-a-time process?

### RS-18 — Student moves from Class 5A to 5B halfway through the term
Does current access change correctly while historical learning evidence remains correct?

### RS-19 — Student transfers to another PINTAR school
Can the intended transferable record move safely across tenant/school boundaries while preserving historical truth?

### RS-20 — Management wants educators to complete a lesson/training package and see who has done it
Does educator-as-learner support this naturally? **Canonical-scope check required.**

### RS-21 — Principal opens PINTAR five minutes before a meeting and needs to understand the school's situation quickly
Does the management experience satisfy the 60-second comprehension principle?

### RS-22 — Someone receives a printed certificate and scans its QR using an ordinary phone without a PINTAR account
Can the person verify authenticity immediately and understand what is being verified?

### RS-23 — Email delivery temporarily fails during staff activation/recovery
Does PINTAR communicate the situation sensibly, allow safe retry/recovery and avoid falsely implying success?

### RS-24 — Sole school administrator forgets password
Can the school recover without an engineer or unsafe database intervention?

### RS-25 — User does something twice because PINTAR appears slow
Examples: assign twice, submit twice, resend twice. Are operations idempotent or otherwise safely handled, and does the interface make the actual state clear?

# 14. “Boring but Deadly” Browser and Product Scenarios

These are not exotic QA cases. They are ordinary browser behaviour and normal user mistakes.

### BD-01 — Browser Back button
What happens after submitting an assessment or completing another irreversible action?

### BD-02 — Browser Refresh
What happens during a lesson, assessment, result screen or assignment flow?

### BD-03 — Double click
Can two assignments, results, messages or certificates be created accidentally?

### BD-04 — Two tabs
The user has PINTAR open in two browser tabs. What happens if state changes in one while the other is stale?

### BD-05 — Expired session
The user has been looking at a page for a long time and then clicks Save.

### BD-06 — Slow connection
The user cannot tell whether an action succeeded.

### BD-07 — Empty state
There are no students, assignments, results or certificates yet. Does the user understand the state and next action?

### BD-08 — Partial state
Some students finished, some have not started and some are halfway. Is this understandable?

### BD-09 — Wrong role
A student attempts to reach a teacher/admin route. Access must be safely refused without leaking protected information.

### BD-10 — Direct old bookmark
A user opens a bookmarked page after permissions, class membership or content state has changed.

### BD-11 — Sign out then browser Back
Does protected information reappear?

### BD-12 — Same account on two devices
Does behaviour remain safe and understandable?

### BD-13 — Name/class/role changes while historical evidence exists
Does current identity update without rewriting historical truth?

### BD-14 — Teacher tries to act on an archived/completed class
Does PINTAR prevent inappropriate changes while still allowing legitimate historical viewing?

### BD-15 — User makes a mistake and wants to undo/correct it
Is there an appropriate correction path without destructive or hidden intervention?

# 15. Cross-Cutting Question — “What Happens Next?”

At every major stage of every journey, ask:

> **Does the user understand what happened and what to do next?**

Examples:

**Student**
- “You finished Chapter 5. Here is what comes next.”
- “This topic needs attention. Review this lesson.”
- “Your work is saved. You can continue later.”

**Teacher**
- “12 of 30 students have not completed this.”
- “Most students struggled with Question 4.”
- “This class needs attention here.”

**Administrator**
- “28 of 30 student accounts are ready. These two need attention.”
- “School setup is incomplete. Complete these items next.”

**Management**
- “Three areas require attention.”
- “This metric changed because…”
- “Start here.”

This principle is central to PINTAR's goal of rapid comprehension. PINTAR should not merely store or display truth. It should help the appropriate person understand the truth and know what to do next.

# 16. Principles for the Later Claude Cross-Check

1. **Do not modify PINTAR yet.**
2. **Do not reinterpret the journey to fit current code.**
3. **Check every journey/scenario against canonical 4.0 scope.**
4. **Identify any item requiring an owner ruling rather than silently expanding scope.**
5. **Trace the current implementation as a human would experience it.**
6. **Do not treat API/RPC/source existence as proof that the human journey is connected.**
7. **Record the exact point where a journey breaks.**
8. **Distinguish CONNECTED, DISCONNECTED, PARTIAL, MISSING, WRONG and UNPROVEN.**
9. **Preserve useful engineering evidence underneath the human status.**
10. **Do not generate fixes or tickets during the cross-check unless explicitly authorised later.**

The ultimate question is not:

> “Does PINTAR contain this feature?”

It is:

> **“Can the person accomplish what they came to PINTAR to do, safely, naturally and without hidden technical help?”**
