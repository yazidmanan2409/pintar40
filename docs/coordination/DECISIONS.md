# PINTAR 4.0 — canonical decisions

Decided by the coordinator unless marked *(Yazid)*. Quote decisions by number.
Changing a decision means adding a new one that supersedes it. Entries are never edited silently.

| # | Date | Decision | Why |
|---|---|---|---|
| **D-001** | 23 Sep | **Gladys is the first and only SYSTEM_ADMIN.** Bootstrapped once, global scope, valid until 23 Sep 2027. A second SYSTEM_ADMIN must be appointed before then. *(Yazid)* | Product owner. The bootstrap door is now closed for good. |
| **D-002** | 23 Sep | **Production runs in the `production` environment, with test fixtures off.** | Runbook §3c. |
| **D-003** | 23 Sep | **SD Zayd Pintar Selalu and SMA Zayd Pintar Selalu are REAL schools, not demo.** *(Yazid)* | Demo evidence never reaches any report, by design. Testers must see the full flow, including reports. Consequence: certificates are real. |
| **D-004** | 24 Sep | **`main` is the only trunk and the only source of production.** Production workflows (deploy, migrations, Auth, SMTP, diagnostics) run only from `main`, and their jobs refuse any other ref. Only the coordinator merges into `main`. Lanes: Bob `claude/quirky-meitner-a04smj`, Daisy `ux-1/daisy-experience`. | Until 24 Sep a push to Bob's branch could change production without any gate. |
| **D-005** | 24 Sep | **Sprint 1 goal: a school can run one lesson end to end through the app.** Done means: <br>(1) the audit journey from an empty school passes with **no operator steps**; <br>(2) a student completes pre-test → lesson → post-test → result; <br>(3) the teacher, the head of department and the school admin each see that class's report. | That is the gap the audit found. |
| **D-006** | 24 Sep | **The school structure maps onto the existing org tree:** <br>INSTITUTION (the school) → FACULTY ("Jenjang", one per school, created automatically, hidden) → DEPARTMENT (**"Bagian"**) → PROGRAMME ("Reguler", created automatically, hidden) → COHORT (**"Tingkat"**, carries the academic year) → CLASS (**"Kelas"**, carries the academic year). <br>Screens show only Bagian, Tingkat and Kelas. <br>Role scopes: Admin sekolah and Dekan at the school, Kepala departemen at a Bagian, Guru at a Kelas. | This matches the data workbook Gladys fills in and keeps the existing, tested database rules. No schema redesign. |
| **D-007** | 24 Sep | **Lesson content v1 is an Excel template, one course per workbook.** <br>Sheets: Kursus, Bab, Pelajaran (lesson text), Soal (questions), Pilihan (answer options, each with its reason). Media files are uploaded alongside and referenced by file name. <br>It is uploaded through a file picker on `/studio/unggah`, parsed on the server, and turned into course, chapters, lessons, questions and options through one database function. <br>The JSON "Paket Terstruktur" path stays, for machine producers, but must work: its confirmation step is fixed. | Gladys and teachers work in Excel. The app currently accepts no file at all. |
| **D-008** | 24 Sep | **Assigning a published lesson to a class creates its pre-test and post-test automatically,** from questions the workbook marks *Pemetaan awal* (pre) and *Cek penguasaan* (post). A lesson without them cannot be assigned, and the teacher is told why in Indonesian. A student never reaches a 404. | Today nothing creates them, so every lesson dead-ends. |
| **D-009** | 24 Sep | **Sign-out and sessions.** <br>"Keluar" is visible on every signed-in screen. <br>Signing out ends the session on **this device only**. <br>Class-card (student) sessions end after **60 minutes without activity**; email accounts after **7 days**. | Shared classroom tablets. |
| **D-010** | 24 Sep | **After signing in, everyone lands on their own home:** Murid → Belajar; Guru → Mengajar; Kepala departemen and Dekan → Pimpinan; Admin sekolah and Admin platform → Konfigurasi. The only exception is a person who asked for a specific page. | Everyone currently lands on `/`, and management loops. |
| **D-011** | 24 Sep | **Errors are never shown raw.** <br>Bob's server code returns stable error codes; Daisy maps each code to Indonesian and English wording in `hle.ts`. <br>An unknown error shows a calm generic message plus a short reference. <br>Error and not-found pages are PINTAR's own, in the reader's language. | Users currently see English database messages and Next.js default pages. |
| **D-012** | 24 Sep | **The gate** (README §5) applies to every change, hotfixes included: <br>a test that fails without the change and passes with it; <br>CI green on the exact commit; <br>lane rules respected; <br>audit journeys run on the candidate. | This is how the front-door fix shipped cleanly. |
| **D-013** | 24 Sep | **Production data changes go only through reviewed, auditable steps.** Where a screen exists, a person does it in the app. Where none exists yet, the coordinator does it through the database with an audit record, and records it in `RELEASES.md`. Never ad-hoc. | The audit trail must stay truthful. |
| **D-014** | 24 Sep | **All user-visible words live in `src/lib/hle.ts`.** Daisy owns the wording. Bob may add keys with his best Indonesian and English, and the key names are the contract. | One place for language; the existing static tests enforce it. |
| **D-015** | 24 Sep | **The quick quiz is "Uji Cepat" everywhere** (not "Kuis Cepat"). | It already has one name in the database and the teacher screens. |
| **D-016** | 24 Sep | **Interim onboarding for the two schools, until BOB-01 and DAISY-05 ship:** <br>the **coordinator** builds each school's Bagian / Tingkat / Kelas in the database from Gladys's workbook, following D-006 and D-013; <br>**Gladys and the school admins** create staff (Aktivasi → "Orang baru di luar pendataan", then Konfigurasi → Peran & akses) and students (Pendataan, one upload per class, then class cards) **in the app**. <br>Teachers are not put through the intake, because the intake would enrol them as students (audit M5). | Only the missing class screen needs an operator. Everything else leaves a real audit trail through the app. |
| **D-017** | 24 Sep | **Supersedes D-016. School data is loaded only after the audit fixes ship.** No classes, staff or students are loaded for SD or SMA until sprint 1 is released. Gladys then builds the structure and adds people herself in the app (DAISY-05 on BOB-01, plus the existing Aktivasi and Pendataan screens), with no operator step. The filled workbook is used then. *(Yazid)* | Onboard once, through the finished product, not through an interim operator path. |
